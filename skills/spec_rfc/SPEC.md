# Spec RFC

用于用户明确要求 RFC，或跨模块变更中需要保留架构权衡、接口兼容、迁移与验收决策的任务。简单修复、清晰的依赖调整无需进入此流程。

先从代码、契约和已有计划提取目标、约束与未知项。能从上下文解决的选择自行作出；只有无法合理推定且会改变结果的事项才提问，同时继续独立工作。

按需要写一份简洁 RFC，包含问题与成功标准、当前与目标行为、关键设计及替代方案、接口兼容/迁移、风险和验证方式。省略不适用部分，不逐阶段生成重复文档。

用户要求仅出方案时停在方案。已授权实现时完成设计后继续编码和验证；只有真实授权缺口或关键需求阻塞才等待，不追加普遍的 RFC 签字门禁。需求变化增量更新同一份文档。
