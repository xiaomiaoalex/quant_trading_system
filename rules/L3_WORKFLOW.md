# 按任务选择工作流

小范围修复：定位真实调用链，修改实现，验证受影响行为并交付。缺陷、状态迁移、幂等与风控修改优先用失败测试复现；普通低风险改动不强制 TDD 仪式。

跨模块或长任务：记录目标、验收条件、依赖和当前进度；有需要权衡或迁移的设计决定时用 `../skills/spec_rfc/SPEC.md`。已有授权且设计缺口能合理解决时，给出简洁方案后继续实施。

验证按变更选择：订单逻辑检查合法/非法迁移、重复、乱序和竞争；风控检查拒绝、降级和恢复边界；持久化检查 append 幂等与回放；端到端链路变化检查相关闭环。合并前遵守当前 `.github/workflows/ci-gate.yml`，不把本地每次小改动等同于发布验收。

文档只更新受影响的事实：接口改动同步契约，架构改动同步图文，阶段或优先级变化同步对应状态/计划。重要开发记录追加到日志，可复用经验才入经验文档。

分支沿用 `feature|bugfix|hotfix|docs/task-{已有编号}/{描述}`，提交沿用 Conventional Commits。PR 说明实际问题、最终行为、验证与必要风险/回滚；有 Task ID 就关联，不发明编号。创建 PR、推送与合并按用户授权及宿主权限执行。
